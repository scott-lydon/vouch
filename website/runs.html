Runs

Every time you run vouch run, this page shows you what happened: which permutations executed against which surface, what each verdict was, which candidate rules the inducer scored, and any clash arbitration findings.

✓

Vouch is live. The dashboard runs locally.

As of 2026-05-22 Vouch ships an end-to-end pipeline. The fixture form in this repo has been mapped (9 actions), planned (51 permutations at depth 2 with rule filtering for type-after-focus), oracle-predicted (heuristic until you set ANTHROPIC_API_KEY, then Haiku), and executed (all 51 pass on the fixture). Real data is in vouch.db; the dashboard renders it with editable operator notes.

The shape is sourced from plan.md §3 (Surface Mapper) and the SQLite schemas in plan.md's persistence layer. Treat the layout below as documentation of what each panel will show, not as data — nothing here is a real measurement.

3. FSM & rule changes (per proposed_rules + rule_history)

schema, not data

Side-by-side diff of the rule set before and after the run. Promotion needs ≥10 confirmations across ≥3 distinct runs and ≥2 calendar days, so most early runs show "candidates created" but zero "promoted." The shape:

4. Clash arbitration findings (per arbiter_decisions)

schema, not data

Only present when a previously-promoted rule starts to deny during this run. The arbiter compares spec.md at promoted_at against the current spec.md and classifies the clash as regression, intentional evolution, or possibly intentional. Every call is audited with prompt sha + raw response. Empty array on most runs.

{
  "findings": [
    {
      "rule_id":           "rule_x9y8",

      "cost_usd":           0.0008,
      "arbiter_decision_id": 42
    }
  ]
}

How this page reads data (the wiring)

Single-file HTML, no build step. The page reads run data from two sources, in this order:

  1. The local filesystem. When you open file:///…/vouch/website/runs.html with a browser that allows local fetch (Safari with Developer → Disable Local File Restrictions ON, or via python3 -m http.server from the vouch/ repo root), the page fetches ../runs/index.json for the manifest and ../runs/<run-id>/index.json for each run.
  2. An optional vouch serve mode. When the CLI ships vouch serve --runs-dir ./runs, it exposes a static read-only server on http://localhost:7321. This page detects the server (probes /health), prefers it when present, and falls back to filesystem reads otherwise.

The runs page never invokes an LLM and never writes to disk. Pure read-only render layer.
